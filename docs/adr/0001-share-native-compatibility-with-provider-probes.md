# Share native compatibility with provider probes

CPA owns request compatibility in shared native execution paths rather than independently reproducing the same behavior in installed plugins or management probes. This records the existing Request and Probe Parity requirement and the approved native direction for the Codex compatibility work; it is not a claim that implementation is complete.

Plugin implementations are reference material: installing overlapping transformations would introduce ordering and state-ownership ambiguity. Production HTTP/WebSocket execution and provider probes must share applicable translation, capability and payload decisions, while probes pin one credential rather than exercising production pool rotation. A basic connectivity result does not certify optional image or patch tools.

The user clarified that Local Compact and Compact Bridge are references for compaction compatibility only: this task does not add a summary-generation service or enable those plugins. CodexComp and CodexCont are references for investigating stream and terminal handling against existing CPA fixes, not a mandate to add automatic continuation. Additional inference is not a prerequisite for repairing these compatibility paths.

Codex Switch Safe informs targeted cleanup of encrypted reasoning bound to a previous route. It does not justify introducing blanket route pinning or rejecting ordinary key/model switches. Readable history and tool results must remain intact. Stored-response references and opaque compaction are distinct from disposable reasoning state; their missing-context edge cases require separate treatment rather than extending reasoning cleanup to all state.

The agreed native scope includes Responses Lite policy consistency and Apply Patch bridge gaps. Lite behavior must remain distinct from explicit image-tool removal. Patch bridging must preserve existing native Codex tool contracts, including Any and Agent routes, rather than globally rewriting custom tools as functions. These choices favor provider capability boundaries over installing overlapping request-transform plugins.

Compaction and stream work extends and verifies existing CPA compatibility fixes. It must preserve meaningful compacted history, terminal outcomes and upstream error details; it must not disguise truncation as success or replay committed tool output. Provider Rate Limiter, Codex Message Translator and DSH Session Affinity remain outside this task.

## Confirmed scope clarification

Reuse the existing Codex provider image-generation switch and its established semantics. Borrow applicable Responses Lite implementation details to close verified gaps; do not introduce another switch or redesign image-tool policy as part of this task.

Provider tests and speed probes follow the current provider/model configuration, including unsaved draft settings and both states of the existing image compatibility switch. The proposed policy of making probes permanently text-only is withdrawn. A probe must exercise the applicable production transformation rather than remove tools independently to obtain a green result. Regression tests must compare production and probe outbound behavior for both switch states; live probes still pin one key.

The user approved completing Apply Patch bridges for Claude and Gemini, regression-testing the existing OpenAI Chat bridge, and preserving native Codex/Any/Agent tool formats. Advertised patch capability must match verified tool definitions, history and response conversion rather than merely exposing a catalog field.
